# Phase 21: UI Scaffolding & Mock Auth

## Objective
Establish a responsive, accessible Admin Dashboard shell using Phoenix LiveView, Tailwind CSS, and Petal Components. Implement a "frictionless" mock authentication system that securely provisions a session for testing without the overhead of real user management or database tables.

## Key Files & Context
- `demo/mix.exs`: Dependency management for Petal Components.
- `demo/assets/tailwind.config.js`: Tailwind configuration for Petal.
- `demo/lib/demo_web/router.ex`: Route definitions for login and admin areas.
- `demo/lib/demo_web/mock_auth.ex`: Frictionless mock auth implementation.
- `demo/lib/demo_web/live/login_live.ex`: The login page.
- `demo/lib/demo_web/live/admin_live/index.ex`: The primary dashboard shell.

## Implementation Steps

1. **Integrate Petal Components**
   - Add `{:petal_components, "~> 2.4"}` to `demo/mix.exs` and run `mix deps.get`.
   - Update `demo/assets/css/app.css` to include Petal's file paths.
   - Import `PetalComponents` into `demo/lib/demo_web.ex` (e.g., inside the `html` block) so they are globally available.

2. **Implement Frictionless Mock Auth**
   - Create a module `DemoWeb.MockAuth` that provides an `on_mount` lifecycle hook for LiveViews and a Plug for standard controllers.
   - The auth logic will simply check the `conn` or `socket` session for a `:mock_user_id`. If absent, it redirects to `/login`.
   - If present, it assigns a static, in-memory `%Demo.Accounts.User{id: "mock-123", name: "Demo Merchant"}` to the assigns.

3. **Build the Login View**
   - Create `DemoWeb.LoginLive` mapped to `/login`.
   - Design a polished, centered login card with a single action: "Login as Demo Merchant".
   - The button triggers an event that redirects the user while writing the `:mock_user_id` to the session via `DemoWeb.AuthController`.

4. **Scaffold the Admin Dashboard Shell**
   - Create `DemoWeb.AdminLive.Index` mapped to `/admin` protected by the `MockAuth` hook.
   - Implement a custom SidebarLayout as the core shell.
   - Follow GDS progressive disclosure: render a high-level "System Status" card and a placeholder for upcoming Paddle integrations.

## Verification & Testing
- **UI-01**: Verify Petal Components are successfully compiled into the asset pipeline without Tailwind errors.
- **UI-02**: Verify a user cannot access `/admin` without authenticating, and that clicking "Login as Demo Merchant" successfully provisions a session and redirects to the dashboard.
- **UI-03**: Verify the Admin dashboard renders the sidebar layout with responsive mobile behavior and dark/light mode compatibility.
