# Phase 22: Core SaaS Checkout & Webhooks

## Objective
Enable a backend-driven checkout flow using `oarlock` and securely persist subscription state via a robust webhook inbox pattern. Provide a seamless LiveView UI experience where successful checkouts update the dashboard in real-time.

## Key Files & Context
- `demo/lib/demo/billing/subscription.ex`: Local Ecto schema for subscription state.
- `demo/lib/demo/billing/webhook_event.ex`: Ecto schema for the persistent webhook inbox.
- `demo/lib/demo_web/controllers/webhook_controller.ex`: Endpoint to receive and verify Paddle webhooks.
- `demo/lib/demo_web/live/admin_live/index.ex`: The dashboard UI to trigger checkout and display subscription status.
- `demo/lib/demo_web/components/layouts/root.html.heex`: Paddle.js script inclusion.

## Implementation Steps

1. **Database Schema & Migrations**
   - Generate Ecto migrations for `webhook_events` (storing raw JSON payloads, paddle event IDs, and processing status) and `subscriptions` (storing `paddle_customer_id`, `paddle_subscription_id`, `status`, and linking to `mock_user_id`).

2. **Webhook Ingestion (Persistent Inbox)**
   - Create `DemoWeb.WebhookController` mapped to `POST /webhooks/paddle`.
   - The controller will read the raw body and use `Paddle.Webhooks.verify_signature/4`.
   - On success, it inserts the raw JSON into `webhook_events`.
   - A synchronous processor will then use `Paddle.Webhooks.parse_event/1` to read the event. If it's a `subscription.created` or `subscription.updated` event, it will upsert the `subscriptions` table. It relies on the `custom_data.mock_user_id` passed during checkout.
   - Upon successful processing, it broadcasts a PubSub message `{:subscription_updated, mock_user_id}`.

3. **Backend-Driven Checkout**
   - Update `DemoWeb.AdminLive.Index` with a "Subscribe Now" button.
   - On click, the LiveView calls `Paddle.Transactions.create/2` with a hardcoded `price_id` (from seeds) and injects `custom_data: %{mock_user_id: @current_user.id}`.
   - Upon receiving the `checkout.url` from `oarlock`, the LiveView pushes an event to the client to open the Paddle.js overlay.

4. **LiveView Real-Time UI**
   - Include Paddle.js in `root.html.heex`.
   - Write a small JS hook in `app.js` to handle the `open_checkout` event pushed from LiveView.
   - Update `DemoWeb.AdminLive.Index` to subscribe to the PubSub topic on mount. When it receives `{:subscription_updated, ...}`, it re-fetches the local subscription from Ecto and updates the UI instantly.

## Verification & Testing
- **CHK-01**: Verify clicking "Subscribe" successfully calls `Paddle.Transactions.create/2` and opens the Paddle overlay.
- **CHK-02**: Verify the webhook endpoint correctly verifies a test payload (simulated or real sandbox) using `Paddle.Webhooks.verify_signature/4` and persists it to `webhook_events`.
- **CHK-03**: Verify the webhook processor successfully hydrates the `%Paddle.Event{}` and upserts the `subscriptions` table, automatically linking it to the `mock_user_id`.
