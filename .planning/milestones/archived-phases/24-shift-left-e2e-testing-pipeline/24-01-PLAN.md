# Phase 24: Shift-Left E2E Testing Pipeline

## Objective
Establish a deterministic, Elixir-native end-to-end testing pipeline for the Demo App. Using `phoenix_test`, we will programmatically simulate the user UI flow (login, dashboard navigation) interleaved with cryptographic webhook simulations to verify the full Paddle integration lifecycle.

## Key Files & Context
- `demo/mix.exs`: Add `phoenix_test` dependency.
- `demo/test/demo_web/integration/billing_flow_test.exs`: The primary E2E integration test file.

## Implementation Steps

1. **Integrate `phoenix_test`**
   - Add `{:phoenix_test, "~> 0.4.1", only: :test, runtime: false}` to `demo/mix.exs`.
   - Run `mix deps.get` to fetch the new testing dependency.

2. **Construct the Webhook Simulator Helper**
   - Create a test helper in `demo/test/support/webhook_simulator.ex` that takes a map of payload data, generates a timestamp, and signs the payload using `:crypto.mac(:hmac, :sha256, ...)` with the configured test secret.
   - This ensures the test webhooks accurately mimic Paddle's cryptographic signatures, verifying our secure ingress pipeline.

3. **Develop the E2E Billing Flow Test**
   - Create `demo/test/demo_web/integration/billing_flow_test.exs`.
   - **Phase A (Unauthenticated)**: Assert that visiting `/admin` correctly redirects to `/login`.
   - **Phase B (Mock Auth)**: Use `PhoenixTest` to fill out the login form or click the "Login as Demo Merchant" button. Assert successful redirection to `/admin`.
   - **Phase C (Checkout Intent)**: Assert the dashboard displays the "Subscribe Now" state.
   - **Phase D (Webhook Simulation)**: Generate a `subscription.created` webhook payload (for the mock user) and use `build_conn()` to `POST /webhooks/paddle`.
   - **Phase E (Real-time PubSub)**: Because `PhoenixTest` wraps LiveView, we can assert that the page *automatically* transitions to the "Manage Subscription" state without reloading, proving our PubSub + Local DB Cache architecture works flawlessly.

4. **CI Readiness**
   - Since this runs inside `mix test`, no extra GitHub Actions configuration is needed. It automatically shifts our E2E webhook tests "left", running deterministically without brittle headless browser setups.

## Verification & Testing
- **E2E-01**: Verify `mix test test/demo_web/integration/billing_flow_test.exs` passes successfully.
- **E2E-02**: Verify the test realistically simulates the cryptographic signature logic that `Paddle.Webhooks.verify_signature/4` enforces.
