<objective>
Implement REL-01: thread an optional `idempotency_key:` opt through every `create/*` public function in the SDK so the caller's deterministic key (e.g., `"accrue:job:#{job_id}:attempt:#{attempt}"`) is forwarded as the `Idempotency-Key` HTTP header on every duplicate-safe POST. Purpose: Lets Accrue (and any other consumer) eliminate double-charges from upper-layer retry semantics — Paddle deduplicates identical POST attempts within its TTL window when supplied the same Idempotency-Key. Per D-06/D-07, the SDK does NOT auto-generate keys; the caller's retry layer owns the decision (auto-gen across retries breaks dedup; AWS Builders' Library + Stripe-Brandur cited in CONTEXT.md). Per D-08/D-09, validation is pass-through except for nil/empty/non-binary rejection (loud failure on bad input).

Output: `Paddle.Http.request/4` extracts `:idempotency_key` BEFORE the Req-bound opts merge (Pitfall 3) and injects an `Idempotency-Key` header; three resource modules (`customers.ex`, `customers/addresses.ex`, `transactions.ex`) gain trailing `opts \\ []` per D-21; adapter-backed tests in `http_test.exs` lock the four behaviors (forwarded, omitted-when-absent, ArgumentError on nil/empty/whitespace, ArgumentError on non-binary); CHANGELOG documents REL-01.
