<threat_model>
## Security Threat Model

**Scope:** Internal pagination helper and per-resource auto-pagination wrappers.

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Absolute `next` URL from Paddle could bypass the configured sandbox/live base URL if sent directly to Req. | medium | Normalize `meta.pagination.next` to `path?query` before calling `Http.request/4`; adapter tests assert sandbox clients do not dispatch to `api.paddle.com` host. |
| Infinite or excess pagination requests if continuation is based on non-nil `next`. | medium | Continue only when `page.meta["pagination"]["has_more"] == true`; add `has_more: false` with non-nil `next` regression tests. |
| Partial eager results could be mistaken as complete data after a later-page failure. | medium | `all/*` returns `{:error, reason}` on the first failure and never returns partial lists. |
| Stream side effects can observe earlier items before a later-page failure raises. | low | Document this behavior in `guides/accrue-seam.md` and `guides/getting-started.md`; lazy streams cannot provide a normal producer error channel. |
| Unbounded memory use from eager `all/*` on large accounts. | low | Document `all/*` as for bounded result sets/scripts; recommend `stream/*` for backfills and early-stop workflows. |

**Blocking threats:** none high severity after mitigations.
</threat_model>
