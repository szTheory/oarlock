# Phase 25: Offline Mode Foundation

## Objective
Establish a standalone, lightweight mock server (`Paddle.MockServer`) embedded within the `oarlock` SDK. This allows developers to test their integrations seamlessly offline without setting up external mocking libraries, honoring the "stripe-mock" paradigm of exceptional developer ergonomics.

## Key Files & Context
- `lib/paddle/client.ex`: Needs to support a configurable `:base_url`.
- `lib/paddle/mock_server.ex`: The primary Plug router for the mock endpoints.
- `lib/paddle/mock_server/fixtures.ex`: A centralized module holding valid simulated JSON payloads.
- `test/paddle/mock_server_test.exs`: Tests verifying the mock server's behavior.

## Implementation Steps

1. **Client Configuration Updates**
   - Update `Paddle.Client.new/1` to accept a `:base_url` parameter. If not provided, it should default to `https://api.paddle.com`.
   - Ensure the internal `req` instantiation in `Paddle.Http` utilizes this `base_url`.

2. **Build the Mock Server Router**
   - Create `Paddle.MockServer`, a `Plug.Router`.
   - Implement `match _` and `dispatch _` callbacks.
   - Define a `start_link/1` function that spawns a `Bandit` server wrapping the router (e.g., `Bandit.start_link(plug: Paddle.MockServer, port: Keyword.get(opts, :port, 4001))`).

3. **Implement Smart Fixtures**
   - Create `Paddle.MockServer.Fixtures`.
   - Extract the hardcoded JSON payloads from our existing test suite (e.g., `seam_test.exs`) into reusable functions like `customer_created/1`, `transaction_created/1`, etc.

4. **Wire Endpoints**
   - Add routes to `Paddle.MockServer` to handle core SDK operations:
     - `POST /customers`: Returns a successful customer creation payload.
     - `GET /customers/:id`: Returns a customer payload dynamically injecting the `id` from the path.
     - `POST /transactions`: Returns a transaction with a dummy checkout URL.
     - `GET /transactions/:id`: Returns a dynamic transaction payload.
     - `POST /customers/:id/portal-sessions`: Returns a simulated portal session URL.

5. **Demo App Integration**
   - Update the Demo App's `config/dev.exs` or `config/test.exs` to optionally point to the mock server port.
   - Add a mix task or application child spec in the demo app to spin up the mock server during tests or offline dev mode.

## Verification & Testing
- **OFF-01**: Verify `Paddle.Client` correctly respects the `:base_url` override and attempts to hit `localhost:4001` when configured.
- **OFF-02**: Verify `Paddle.MockServer.start_link/1` successfully binds a local port and responds to a `GET /customers/ctm_123` with a valid JSON payload containing `"id": "ctm_123"`.
- **OFF-03**: Verify the Demo App's integration test suite can optionally run entirely offline against the Mock Server without hitting external Paddle APIs.
