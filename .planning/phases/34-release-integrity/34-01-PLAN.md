<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow_dispatch → release runner | Maintainer tag text crosses into Git and shell operations. |
| GitHub CI/run/artifact APIs → candidate packet | Remote hosted proof is authoritative only after exact identity validation. |
| candidate packet → Hex publish environment | External registry mutation gains an organization credential. |
| Hex registry → evidence asset | Public metadata and tarball bytes must agree before durable success is recorded. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-01 | Spoofing | tag and CI candidate | high | mitigate | Task 1 peels the remote tag and requires Phase 33's exact-SHA run, attempt, jobs, and artifact identity; Task 2 rejects mismatches. |
| T-34-02 | Tampering | package handoff and Hex bytes | high | mitigate | Task 1 records the Mix outer checksum and compares Hex metadata and fetched tarball before evidence. |
| T-34-03 | Elevation of privilege | publish credential | critical | mitigate | Task 1 puts `HEX_API_KEY` only on the final Mix publish step after credential-free preflight and lock revalidation. |
| T-34-04 | Information disclosure | errors and evidence | medium | mitigate | Task 2 uses sanitized identity-only errors and Task 1's compact evidence packet excludes credentials and payloads. |
</threat_model>
