  <name>Task 1: Prove candidate-to-Hex checksum agreement and consumer installability</name>
  <files>scripts/release_integrity.cjs, scripts/release_integrity.test.cjs, bin/package_smoke.sh</files>
  <behavior>
    - A clean tagged checkout's `mix hex.build --output` emits one `oarlock` package whose outer SHA-256 matches the independent file hash; a second pinned build after dry run matches the same checksum.
    - Hex release API version/checksum and the SHA-256 of its fetched repository tarball both equal the candidate checksum, and unpacked package metadata names `oarlock` at the derived version.
    - A fresh Mix consumer depending on the fetched published version compiles with warnings as errors; a local unpacked package or a version endpoint alone does not satisfy that result.
    - Malformed, unavailable, or mismatched metadata or tarball bytes stop evidence generation with expected and observed digests.
  </behavior>
  <action>Per D-04, confirm the supported Hex 2.5.1 `mix hex.build --output` outer-checksum representation against SHA-256 of the generated candidate tarball and Hex's API `checksum` field. In secret-free preflight, build twice under the pinned `.tool-versions`/Hex toolchain around `mix hex.publish --dry-run --yes`, confirm deterministic byte checksum and package metadata, and capture useful Mix package warnings; stop on parity failure. Do not alter checkout, package files, or toolchain between candidate proof and actual publish. Per D-05, poll the exact Hex release version within a bounded interval after publish, parse its version/checksum strictly, download the repository tarball, compare both digests to the candidate, and inspect package metadata. Extend `bin/package_smoke.sh` with a published-version mode that obtains the served tarball in a temporary directory, declares an exact-version dependency equivalent to `{:paddle, "== X.Y.Z", hex: :oarlock}` in a new consumer, runs `mix deps.get`, and compiles with warnings as errors; preserve the existing local-artifact mode for CI. Gate evidence success on all observations. Add focused mismatch and clean-consumer fixtures before implementation, including checksum encoding and malformed API response cases. Follow scripts/ci_remote_gate.cjs for bounded CLI observations, scripts/ci_remote_gate.test.cjs for injected failure fixtures, and bin/package_smoke.sh for temporary consumer construction, as assigned in 34-PATTERNS.md.</action>

  <name>Task 2: Reconcile ambiguous Hex outcomes without changing published bytes</name>
  <files>scripts/release_integrity.cjs, scripts/release_integrity.test.cjs</files>
  <behavior>
    - Before upload, an existing matching version/checksum returns idempotent success with its Hex URL and no upload call.
    - After a timeout or unclear CLI result, a matching release/checksum returns idempotent success; an absent release permits a retry only after tag, proof, version, and checksum revalidation under the lock.
    - A different checksum, malformed response, or unavailable registry observation never triggers an upload or overwrite and reports expected/observed version and digest with a safe incident action.
  </behavior>
  <action>Per D-06 and D-07, make the post-lock Hex state observation the publication decision authority. Model `absent`, `matching`, `conflict`, and `unobserved` outcomes from exact package/version metadata plus checksum. Before the first upload or any retry, rerun remote tag peel, Phase 33 exact-SHA proof/artifact, Mix version and candidate checksum checks inside the shared lock. If Hex already serves the matching checksum, return idempotent success and continue post-publish verification; if confirmed absent after a failed/unclear submission, permit one revalidated publish attempt; if a different checksum exists, stop with an incident message. Bound polling and distinguish a transient not-yet-indexed response from an authoritative absence after the interval. Preserve standard `mix hex.publish --yes` and forbid automatic replacement or revert. Per D-11, emit short structured diagnostics with the check name, expected/observed identity, tag/run/Hex links, and safe next step; redact credentials, raw API bodies, and tarball contents. Create state-transition fixtures before implementing and prove no upload for matching, conflicting, or unobserved outcomes. Keep the release helper's result shape and failure fixtures aligned with scripts/ci_remote_gate.cjs and scripts/ci_remote_gate.test.cjs, the assigned analogs in 34-PATTERNS.md.</action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mix build → candidate packet | Local build output becomes the checksum claim for external publication. |
| Hex API and repository → verifier | Public registry responses can be delayed, malformed, stale, or contradictory. |
| ambiguous CLI result → retry decision | A lost publish response cannot authorize blind mutation of an immutable version. |

| T-34-10 | Spoofing | version endpoint | medium | mitigate | Task 1 requires checksum, retrieved bytes, package metadata, and clean consumer compile rather than an endpoint status. |

</threat_model>
