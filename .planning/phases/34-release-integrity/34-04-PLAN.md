## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verification packet → public GitHub Release asset | Checked facts become a durable public statement about source and published bytes. |
| repository settings API → release policy gate | Remote tag and environment policy must be observed, not inferred from workflow text. |
| GitHub-write token → Release asset | A write-capable token creates or changes maintainer-facing release evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-13 | Repudiation | release manifest | high | mitigate | Task 1 binds repository, tag/SHA, CI run/attempt/artifact, release run, checksums, and verification timestamps in a versioned asset. |
| T-34-14 | Information disclosure | evidence serializer | high | mitigate | Task 1 allowlists IDs, URLs, digests, statuses, and caveats and rejects raw logs, credentials, and payloads. |
| T-34-15 | Tampering | tag and prior asset | high | mitigate | Task 2 protects version tags; Task 1 compares any prior manifest and retains compatible attempt history or stops on contradiction. |
| T-34-16 | Elevation of privilege | Release write job | high | mitigate | Task 1 gives only the asset job `contents: write` and no Hex key; Task 2 verifies the environment boundary remotely. |
</threat_model>
