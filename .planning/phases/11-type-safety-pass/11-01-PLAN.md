<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public seam source -> consumer expectations | Typespecs become part of the SDK contract that Accrue and other callers rely on for correctness and autocomplete. |
| Future contributor changes -> CI tooling | The mechanical gate decides whether a newly added public function is allowed to merge without a spec. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | Public request option contracts | mitigate | Encode the locked `idempotency_key:` / `retry:` vs pause/resume lifecycle vocabularies exactly in `@type request_opt`, `pause_opt`, and `resume_opt` per D-05 so spec drift becomes review-visible. |
| T-11-02 | Repudiation | Public error/result contracts | mitigate | Spell out tagged returns and known local validation atoms in `@spec` declarations per D-06 so callers and CI can distinguish local validation failures from `%Paddle.Error{}`. |
| T-11-03 | Spoofing | Mechanical spec coverage gate | mitigate | Restrict `mix typecheck.specs` to the explicit non-sealed public seam files and emit file/function/arity failures so skipped or unspecced defs cannot hide behind vague output per D-18..D-20. |
| T-11-SC | Tampering | Dependency/install surface | accept | No new third-party package installs occur in this plan. |
</threat_model>
