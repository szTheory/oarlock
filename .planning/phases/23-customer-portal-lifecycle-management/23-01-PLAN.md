# Phase 23: Customer Portal & Lifecycle Management

## Objective
Enable users to securely manage their subscriptions via the Paddle Customer Portal. Expand the webhook processor to elegantly handle the entire subscription lifecycle (e.g., cancellations, pauses) using a unified upsert strategy, ensuring the LiveView UI remains instantly synced with the external billing state.

## Key Files & Context
- `demo/lib/demo_web/live/admin_live/index.ex`: The dashboard UI where the Portal button will be added.
- `demo/lib/demo_web/controllers/webhook_controller.ex`: The webhook ingestion point to be expanded for lifecycle events.

## Implementation Steps

1. **Expand Webhook Processor for Lifecycle Events**
   - Update `DemoWeb.WebhookController.process_event/1` to handle a broader array of subscription events, including `subscription.canceled`, `subscription.past_due`, and `subscription.paused`.
   - Because all these events contain the `%Paddle.Subscription{}` struct in their `data` payload, we can route them through the existing `handle_subscription_change/1` function. This provides a unified, robust upsert mechanism that simply syncs the current `status` and `current_period_end`.

2. **Implement Portal Session Generation**
   - Update `DemoWeb.AdminLive.Index` to add a `handle_event("open_portal", ...)` function.
   - When triggered, it will instantiate the `Paddle.Client`, extract the `paddle_customer_id` from the current local subscription, and call `Paddle.PortalSessions.create/2`.
   - Upon receiving the `portal_session.urls.general.url`, it will use `Phoenix.LiveView.redirect(socket, external: url)` to hand the user off to Paddle.

3. **Enhance the Dashboard UI**
   - In `DemoWeb.AdminLive.Index`'s `render/1`, remove the "Portal (Soon)" placeholder.
   - Inside the "Subscription Active" card (when `@subscription` is present and active), add a "Manage Subscription" button mapped to the `open_portal` event.
   - Use `phx-disable-with` or a loading assign to provide immediate UI feedback while the portal session is generated.
   - Ensure the UI gracefully degrades back to the "Subscribe Now" state if the subscription status becomes `canceled`.

## Verification & Testing
- **PRT-01**: Verify clicking "Manage Subscription" successfully calls `Paddle.PortalSessions.create/2` and redirects the browser to the secure Paddle portal.
- **PRT-02**: Verify the webhook endpoint correctly processes a simulated `subscription.canceled` event, upserts the local DB to reflect the canceled status, and triggers a PubSub update that resets the UI back to the "Subscribe Now" checkout state.
