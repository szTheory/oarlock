<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docs reader -> app implementation | Phoenix/Plug/Ecto snippets may be copied into real apps and must preserve security boundaries. |
| webhook endpoint -> event trust | Paddle webhook payloads are untrusted until verified from the exact raw request body. |
| demo MockServer -> Paddle provider | Demo local proof must not be treated as sandbox/live provider proof. |
| signed-in app user -> portal handoff | Demo and docs must state app-owned authorization before creating or redirecting to portal sessions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-27-06 | Information Disclosure | Sandbox/live credentials in docs | mitigate | Document environment-specific API keys and webhook endpoint secrets; do not hardcode real secrets per D-12. |
| T-27-07 | Repudiation | Demo Offline Mode claims | mitigate | Use proof ladder wording and state MockServer is deterministic local proof only per D-09 through D-11. |
| T-27-08 | Elevation of Privilege | Portal handoff docs | mitigate | State signed-in authorization, provisioning, entitlement, and persistence decisions are app-owned per D-06 and D-19. |
| T-27-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are planned; RESEARCH.md Package Legitimacy Audit recommends none. |
